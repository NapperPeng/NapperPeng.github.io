# v2 字体改造需求：Outfit + MiSans + JetBrains Mono

状态：已获用户批准，已进入实现阶段  
日期：2026-10-27  
对应范围：v2 第二阶段——字体与排版

## 1. 目标

将当前依赖系统默认字体的页面，改为一套有明确视觉识别、适合中英混排且适合技术博客阅读的字体系统：

- 英文标题与界面：Outfit
- 中文标题与正文：MiSans
- 代码、终端示例和等宽数据：JetBrains Mono

本阶段只调整字体和与字体直接相关的排版参数，不改变页面结构、颜色、鼠标样式或按钮动画。

## 2. 字体角色

### 2.1 Outfit

用于英文标题、英文导航、英文按钮、英文标签和英文界面文本。

Outfit 提供现代几何感和较强的英文辨识度，使标题与导航比系统默认字体更有个性，但不使用装饰性字体影响信息传达。

### 2.2 MiSans

用于中文标题、中文正文、中文说明、中文元信息及中文界面文本。

MiSans 负责中文字符的统一字形和中英文混排时的视觉平衡。中文内容不应因为 Outfit 的英文风格而回退到不一致的系统字形。

### 2.3 JetBrains Mono

用于 Markdown/MDX 代码块、行内代码、键盘标记、终端命令和需要等宽对齐的数据。

代码字体保持现有 JetBrains Mono 方向，不替换为其他更具装饰性的等宽字体。

## 3. 字体资源与授权

- 使用可合法分发的字体文件，并在项目文档或资源目录中记录来源与许可证。
- Outfit、JetBrains Mono 和 MiSans 优先使用官方发布的 WOFF2/WOFF 资源。
- 字体文件应放在 `public/fonts/`，由 Astro 通过 `@font-face` 加载；不依赖运行时外部 CDN。
- 如果 MiSans 的具体发行包不适合直接放入仓库，必须在实现前确认可用版本、许可证和部署方式；不得下载来源不明的字体文件。
- 本阶段不将字体文件提交到 `src/assets` 作为图片资源处理，也不把字体加载写成第三方脚本。

建议的资源命名：

```text
public/fonts/
├── Outfit-Variable.woff2
├── MiSans-Variable.woff2
└── JetBrainsMono-Variable.woff2
```

实际文件名可以根据获得的官方资源调整，但 CSS 字体族名称必须保持以下语义：`Outfit`、`MiSans`、`JetBrains Mono`。

## 4. 字体加载策略

- 使用 `@font-face` 声明字体，并设置 `font-display: swap`，避免字体加载失败时页面不可读。
- 只预加载首屏确实使用的主要字体资源；不得无条件预加载所有字重和所有中文分片。
- 优先使用可变字体；如果资源只有静态字重，只加载实际使用的 400、500、600、700。
- 中文字体应尽量使用官方子集、分片或 `unicode-range`，控制首屏传输体积。
- 在字体加载失败时，页面仍使用明确的系统回退字体，不得出现空白文字或布局崩坏。
- 不改变现有 Astro 静态输出方式，不增加字体运行时检测脚本。

建议的回退顺序：

```css
--font-sans:
  "Outfit",
  "MiSans",
  "Noto Sans SC",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;

--font-mono:
  "JetBrains Mono",
  "SFMono-Regular",
  Consolas,
  monospace;
```

Outfit 与 MiSans 的顺序允许按实际中英混排截图调整，但中文不能完全依赖 Outfit 的字形回退。

## 5. 排版基线

这些值是实现起点，允许在截图复核时小幅调整，不改变字体角色。

| 场景 | 字号 | 字重 | 行高 |
| --- | ---: | ---: | ---: |
| 页面主标题 | `clamp(2rem, 4vw, 2.75rem)` | 700 | 1.2 |
| 文章列表标题 | 1.375–1.5rem | 600–700 | 1.35 |
| 文章正文 | 1.0625–1.125rem | 400 | 1.8 |
| 导航与主要控件 | 0.875–1rem | 500–600 | 1.4 |
| 日期、标签和辅助说明 | 0.8125–0.9375rem | 400–500 | 1.5 |
| 代码块与行内代码 | 0.875rem 起 | 400–500 | 1.6–1.7 |

- 正文继续左对齐，不强制两端对齐。
- 正文阅读宽度保持当前开放式布局约 720px 的约束。
- 中文正文使用较宽松的行高，避免 MiSans 在长段落中显得拥挤。
- 标题和导航可使用 Outfit 提供的字形对比，但不要通过过度加粗制造层级。
- 英文全大写只在内容本身需要时使用，不新增装饰性全大写标签。
- 代码块不得继承普通正文的字体、字距或行高。

## 6. 应用范围

### 6.1 全局

- `body` 使用新的 `--font-sans`。
- 标题、导航、作者信息、页脚、按钮、标签和分页控件继承全局无衬线字体，除非有专门规则。
- 现有明暗主题、颜色、间距和开放式布局保持不变。

### 6.2 Markdown/MDX 内容

- 段落、标题、列表、引用、提示块、表格和脚注使用 `--font-sans`。
- `code`、`pre`、键盘标记使用 `--font-mono`。
- 代码块保留自身背景、横向滚动和语法高亮，不因字体改造改变代码块结构。
- 中英文、数字、标点混排时不得出现明显的基线跳动、字宽异常或文本溢出。

### 6.3 组件

- Header、ThemeToggle、PostCard、作者介绍、Footer、分页和时间轴均迁移到新的字体变量。
- 不能只修改首页或文章页；全站页面必须使用同一字体系统。
- 不因字体引入而重新设计导航、鼠标或按钮动画。

## 7. 性能与无障碍要求

- 首屏字体请求数量和资源体积应可解释；不加载未使用的字重。
- 字体加载期间页面保持可读，加载完成后不应产生明显的布局跳动。
- 字体不能降低正文、辅助文字、链接和焦点状态的可读性。
- 保持现有键盘焦点、触控尺寸和 `prefers-reduced-motion` 行为。
- 不使用字体图标替代现有语义图标；Lucide 图标系统保持不变。

## 8. 实现步骤

1. 确认 Outfit、MiSans、JetBrains Mono 的具体文件版本、许可证和字重范围。
2. 添加字体资源与 `@font-face`，定义全局字体变量和回退栈。
3. 将全局正文、标题、Markdown 和代码样式迁移到字体变量。
4. 调整必要的字号、字重、行高和标题换行规则。
5. 在首页、博客列表、文章详情、归档、日记、标签页和 404 页面完成桌面/手机截图复核。
6. 进行生产构建、字体请求检查和跨页导航回归。
