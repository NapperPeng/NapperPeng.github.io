# v2 第一阶段需求：开放式个人博客布局

状态：已获用户批准，进入实现阶段  
日期：2026-10-27  
方案：A · 开放式个人博客

## 1. 目标与设计定位

将当前由多个独立卡片组成的界面，改为共享页面背景、以留白和对齐建立层级的开放式个人博客。

网站仍以作者介绍、技术文章和日记为核心，优先满足访客了解作者、浏览文章及连续阅读的需求。个性来自真实作者信息与内容，而不是额外添加装饰。

本阶段完成后应体现三个变化：

- 页面不再被白色或深色面板切分，导航、标题和内容形成连续的阅读空间。
- 文章列表更像文章目录，而不是一组可点击卡片。
- 去除外框后仍有清晰的信息层级、阅读宽度和可操作性。

## 2. 范围与边界

### 2.1 本阶段包含

- 全站公共布局：页面背景、导航、页标题、正文容器、页脚。
- 首页：作者介绍及现有首页正文。
- 博客列表、标签列表、标签下文章列表及分页。
- 文章详情、独立内容页面、归档、日记和 404 页面。
- 上述页面的移动端适配、明暗主题适配和基础无障碍检查。

### 2.2 本阶段不包含

- 自定义鼠标样式。
- 按钮动画重设计、新增悬停特效或磁吸效果。
- 字体家族更换、字体文件引入及字体加载优化。
- 新增搜索、目录、评论、推荐文章、后台或其他功能。
- 修改文章内容、作者资料、导航名称、站点语言或 URL 结构。
- 调整内容集合、文章排序规则、标签逻辑和每页文章数量。
- 全新品牌配色、插画、游戏化视觉或复杂背景纹理。

允许为新布局调整标题字号、行高、字重和间距；继续使用现有字体栈。保留现有强调色与主题切换机制，仅调整实现统一页面背景所必需的颜色。

## 3. 全局布局要求

### 3.1 开放式表面

- 页面使用统一背景；主要内容区域不再设置独立底色、外框、投影和面板式圆角。
- 移除标题面板、作者面板、文章外壳及列表项外壳，而不是只将圆角改成直角。
- 不采用卡片网格，不增加侧边栏，不改成密集报纸分栏。
- 主要依靠留白、字号、字重和对齐区分内容。细分隔线只在辅助分组确有必要时使用，不为每个区块添加装饰线。
- 不新增装饰编号、英文眉题、渐变光晕或无实际含义的图形。

### 3.2 宽度、对齐与间距

以下数值作为实现起点，可在截图验证时小幅调整，但不得改变布局方向：

| 项目 | 约束 |
| --- | --- |
| 桌面站点容器 | 最大宽度约 1024px，居中 |
| 文章详情及独立页面阅读区 | 最大宽度约 720px；标题、元信息和正文共享左边界 |
| 常规列表及首页 | 在站点容器内左对齐，不为填满宽度强行分栏 |
| 手机页面左右间距 | 约 20px；320px 窄屏可降至 16px |
| 平板页面左右间距 | 约 24–32px |
| 主要区块纵向间距 | 手机约 32–48px，桌面约 48–64px |
| 文章列表项间距 | 约 28–36px，避免因留白过多降低浏览效率 |

正文左对齐，不强制两端对齐。长标题允许自然换行，不能挤压日期或造成整页横向滚动。

### 3.3 导航与页脚

- 桌面导航保留站点名称、现有导航入口和主题按钮。
- 导航主体采用紧凑、整体居中的横向组合：博客名与导航按钮组之间缩小间距，不再使用分散到容器两端的大面积空白。桌面端组间距以约 24–32px 为起点，导航按钮之间以约 8–12px 为起点；可随实际文字宽度微调。
- 在导航主体左右两端各增加一条细横线，形成“左横线—博客名—导航按钮—主题按钮—右横线”的排列。横线位于导航同一行，不是导航的上下边框，也不围成面板。
- 两侧横线等长、随剩余空间弹性伸缩，粗细以 1px 为起点，使用适配明暗主题的低对比度颜色；与导航主体之间保留约 16–24px 间距，不抢占文字视觉重点。
- 手机端优先保证博客名、菜单按钮和主题按钮的空间；横线可随可用空间缩短，在窄屏空间不足时隐藏，不挤压控件或引发横向溢出。
- 取消导航作为悬浮圆角卡片的外观：默认与页面背景融合，无独立阴影和面板边界。
- 保留顶部吸附能力；导航整栏始终透明，滚动和切换主题时均不显示背景遮罩、毛玻璃或背景过渡效果（根据用户后续反馈修订）。
- 保留当前页面识别状态，可调整静态样式以适配无卡片导航；不新增动画。
- 手机保留菜单按钮、展开菜单、点击外部关闭和 Escape 关闭能力；展开区融入导航，不做新的悬浮卡片。
- 页脚延续页面背景，保留原有信息与链接，通过上方留白与正文区分。

桌面导航结构示意（横线实际长度随屏幕宽度变化）：

```text
──────  NapperPeng   Home  Blog  Journal   主题按钮  ──────
```

## 4. 页面级需求

### 4.1 首页

- 保留现有首页标题、作者简介、头像、详细介绍、位置、社交链接及首页正文，不新增内容模块。
- 页标题与作者介绍连续呈现；允许重新组织间距，但不删除现有信息或新增重复标题。
- 作者介绍采用开放式组合：桌面头像与文字并排，手机按空间自然堆叠。
- 保留头像本身的圆形裁切；头像圆形不属于需要移除的卡片结构。
- 首页正文取消外层白色/深色面板与投影，并限制长段落阅读宽度。

### 4.2 博客列表与标签下文章列表

- 文章按现有顺序纵向排列，保留标题、摘要、日期和标签。
- 取消文章项底色、圆角外框、阴影、标题旁蓝色竖条和右侧独立大箭头按钮。
- 日期改为普通辅助文本，不再使用日期底块；标签改为轻量文本链接，不再堆叠成显著色块。
- 标题为明确的文章入口；标签维持独立链接，不能因整行嵌套链接而失去可操作性。
- 标题正常换行；列表摘要最多展示两行，缺少摘要时不留占位空白。
- 标签、归档入口改为紧凑的文字导航，不再作为两块大卡片展示。
- 分页保留上一页、下一页、页码及禁用状态，位置与列表阅读轴保持协调；小型功能控件允许保留必要边界。

### 4.3 文章详情与独立内容页面

- 页标题、说明、发布日期、标签及正文形成同一阅读流。
- 移除标题和正文各自的卡片容器，不再形成上下两个独立面板。
- 标题和正文共享阅读区宽度，正文不因移除内边距而铺满 1024px。
- 保留 Markdown/MDX 的标题、链接、列表、图片、表格、引用、提示块、代码块和脚注能力。
- 保留阅读进度和返回顶部功能。
- 宽代码块及宽表格在自身区域内横向滚动，不能撑宽整页。

### 4.4 归档与日记

- 移除包裹整个时间轴的背景面板、投影和外层圆角。
- 保留年份、日期、时间轴节点及现有顺序，因为这些结构表达真实时间关系。
- 时间轴线条降低视觉权重，正文优先；年份、日期与内容保持稳定对齐。
- 手机端缩减日期栏和节点占位，优先保障标题及日记正文宽度。
- 归档标题和日记内容不能因窄屏重叠；现有归档长标题截断可保留，但链接应包含完整标题文本。

### 4.5 标签索引、404 与空状态

- 标签索引改为可换行的文字索引，保留标签链接及数量信息，取消标签卡片底色和投影。
- 404 保留现有提示和返回入口，以文字与留白呈现，不设置大面板。
- 无文章、无标签和无日记等空状态保留现有含义，不再用空卡片占据大面积空间。

## 5. 去卡片化的例外

去卡片化针对页面组织结构，不要求删除一切背景、圆角或边框。

以下元素可以保留功能性边界，但不额外增加投影或装饰层：

- 代码块、行内代码、键盘按键标记。
- Markdown 提示块、引用及表格的必要区分。
- 图片本身的适度圆角、圆形头像。
- 分页、主题按钮、菜单按钮、返回顶部等小型控件的必要状态表达。
- 工具提示和键盘焦点轮廓。

上述例外不得重新演变为包裹整页或整篇文章的面板。

## 6. 交互与无障碍要求

- 所有原有链接、分页、主题切换、手机菜单、工具提示和返回顶部可正常使用。
- 不依赖悬停才能发现主要入口；触屏和键盘用户可以识别并操作链接。
- 保留可见的键盘焦点，菜单状态与辅助技术属性保持同步。
- 普通文本对比度至少达到 4.5:1，大号文本至少达到 3:1；可操作控件不使用过淡的颜色。
- 独立图标按钮的触控区域目标至少为 44 × 44px；视觉图标本身可小于该尺寸。
- 保留减少动态效果支持。本阶段不增加入场动画，不刻意改变原有转场节奏。
- 原有动效若绑定已移除的卡片结构，仅作必要迁移或删除，不借此扩展为动效重设计。

## 7. 实现约束

- 继续使用 Astro、Tailwind CSS 与原生 TypeScript，不为布局改造增加前端框架或动画依赖。
- 在全局样式中集中管理必要的容器宽度、页面背景和间距，组件局部规则保持清晰。
- 逐处清理旧面板类，不通过大范围全局覆盖或大量 `!important` 掩盖旧样式。
- 允许将 `PostCard`、`AboutProfileCard` 重命名为符合新职责的组件；重命名不改变数据接口和业务逻辑。
- 保持现有路由、静态构建方式和站点配置兼容，不修改生成产物作为实现方式。
- 遵循项目 AGENTS.md；如需启动开发服务，使用规定的后台模式并管理其状态。

## 9. 确认后的实施顺序

1. 改造公共布局、导航和基础样式，完成首页、博客列表、文章详情三种代表页面。
2. 检查代表页面的宽度、留白和信息层级，再将同一规则覆盖到其他页面。
3. 完成响应式、明暗主题、交互回归、生产构建和截图验证。

本文件是布局需求，不是最终像素级设计稿。实现时允许在上述范围内调整间距和尺寸；若涉及删减信息、新增功能或改变视觉方向，需再次征求用户确认。

## 10. 本次审阅需确认

- 是否接受全站统一去卡片化，而非仅修改博客列表。
- 是否接受“站点容器及列表约 1024px、文章阅读区约 720px”的宽度关系；导航主体在容器内紧凑居中，两侧横线弹性延伸。
- 是否接受移除文章右侧大箭头、日期底块和显著标签色块，改以标题与文本链接作为入口。
- 是否接受本阶段保留现有字体、强调色及动效机制，不同步推进其余三个 v2 目标。

在用户明确确认前，只交付与修订本需求文档，不修改布局代码。
