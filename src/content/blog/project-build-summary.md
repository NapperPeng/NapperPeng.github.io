一个个人博客不只是把文章显示出来，还需要解决内容管理、页面结构、阅读体验和部署维护等问题。本文以这个项目为例，简要记录构建类似网站时可以参考的思路。

## 一、先确定网站的内容模型

在开始写页面之前，先区分不同类型的内容：

- **Blog**：存放相对完整的文章，可以使用标签、分页和归档组织。
- **Journal**：记录开发过程、想法和短笔记，适合时间线展示。
- **Page**：存放首页介绍等独立页面。

Astro 的 Content Collections 很适合处理这种结构。可以为每个集合定义 frontmatter schema，例如文章需要 `title`、`description`、`pubDate` 和 `tags`，这样在构建阶段就能尽早发现内容格式错误。

## 二、用内容集合驱动页面

文章文件只负责保存内容和元数据，页面负责展示规则。例如：

```text
src/content/blog/       博客文章
src/content/journal/    Journal 记录
src/content/page/       独立页面
src/content.config.ts   集合和字段定义
```

页面通过 `getCollection` 或 `getEntry` 读取内容，再根据日期、标签和分页规则生成静态路由。这样新增文章时只需要创建一个 Markdown 文件，不必手动修改文章列表页面。

## 三、先搭建稳定的页面骨架

项目使用共享的布局组件处理页面公共部分：导航栏、主题切换、页脚、返回顶部、全局提示和自定义鼠标都由布局统一加载。

这种方式可以避免每个页面重复编写公共结构，也能让视觉调整集中在少数组件中完成。页面本身只需要关注标题、文章列表或正文内容。

## 四、开放式布局比卡片堆叠更适合阅读

本项目的视觉调整重点是去除主要内容的卡片外壳，使用共享背景、留白和文字层级组织内容。文章列表保留清晰的标题、摘要、日期和标签，但不再依赖大面积边框、阴影和圆角来分割每一篇文章。

设计类似页面时，可以优先确定以下内容：

1. 阅读区域的最大宽度。
2. 标题、摘要、元信息之间的间距。
3. 移动端的换行和触控区域。
4. 首页、列表页和详情页各自的对齐方式。

先确定这些基础规则，再添加动画和装饰，页面会更容易保持一致。

## 五、字体需要按用途分工

本项目使用三类字体：

- **Outfit**：英文界面和标题。
- **MiSans**：中文内容和中文界面。
- **JetBrains Mono**：代码块和等宽信息。

字体文件放在 `public/fonts/` 中本地加载，可以减少对外部字体服务的依赖。使用第三方字体时，需要同时保留授权文件，并确认字体授权允许以网站资源形式分发。

## 六、交互要服务于内容

自定义鼠标和按钮交互可以增强识别度，但不能影响基本可用性。本项目的文章列表将整篇文章作为可点击区域，标签仍然保留独立链接；鼠标靠近交互元素时显示四角框和连线，并根据鼠标相对元素中心的位置计算文章块偏移。

实现这类效果时，建议保留以下降级策略：

- 触摸设备继续使用原生触控交互。
- 用户开启减少动画时关闭复杂移动效果。
- 所有交互元素仍然提供真实的键盘焦点和链接行为。
- 鼠标效果只作为视觉反馈，不承担导航逻辑。

## 七、部署前要把开发问题和生产问题分开

Astro 项目可以生成纯静态文件，因此上线时不需要常驻 Node.js 服务。构建过程会把 Markdown、组件和样式转换为 `dist/` 中的 HTML、CSS、JavaScript、字体和图片。

使用 GitHub Pages 时，可以让 GitHub Actions 完成以下流程：

```text
推送 main 分支
→ 安装 Node.js 和 pnpm
→ 安装锁定版本的依赖
→ 执行 astro build
→ 上传 dist
→ 发布到 GitHub Pages
```

生产环境只负责托管生成后的静态文件。上线前应确认 `site` 使用正式域名、根路径配置正确，并检查首页、文章详情、标签、归档、Journal、robots.txt 和 sitemap。

## 八、适合类似项目的开发顺序

如果要从零开始制作一个类似网站，可以按下面的顺序推进：

1. 确定内容类型和 frontmatter 字段。
2. 建立 Content Collections 和基础路由。
3. 完成共享布局、导航和主题切换。
4. 先实现文章列表、详情、标签和归档。
5. 再确定字体、间距和响应式规则。
6. 最后加入自定义鼠标、按钮动画等增强交互。
7. 使用生产构建验证所有静态路由。
8. 配置 GitHub Actions 并部署到 GitHub Pages。

最重要的经验是：先让内容流转和页面结构稳定，再做视觉和交互打磨。这样即使后续更换布局或字体，也不会破坏文章管理和发布流程。
